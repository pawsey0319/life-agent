## 背景与原始诉求
面向先由本人使用、后向少量朋友开放的生活个性化平台。用户希望拥有唯一、长久陪伴的个人 Agent（PA），而不是不断重新建立关系的工具；不同专业 Agent 能提供服务，但不能因此共享所有私人生活。原始诉求是依据两份方案重新开发并提交 life-agent，不是复制旧宠物原型。

PA 提供陪伴、通用事务、专业调度和权限守护。记忆长期重要性与当下活跃度分开，让关键边界不因时间被遗忘，也避免把闲聊永久保存。信息由本人决定保存和分享，拒绝隐式专业数据互通。

## 目标、范围与指标
- 本次：M0，Expo Web/Android 源码、Node Runtime、Supabase 数据底座、PA、记忆手账、自定义 Agent、授权、一次性日程与站内提醒、导出和注销。
- 不含：M1 穿搭师、外部适配器、社交、商业市场、复杂进化、重复日程。后续路线保留，不因分期取消。
- 验收目标：300条人工标注各项≥90%、核心保持≥98%、安全规则召回100%、未经同意敏感写入0；这些是待真实评测的目标，不是已有结果。本人连续一周体验不能自动化替代。

## 需求设计与验收
### LA-001 唯一 PA
用户生成外观候选，选择后永久确认；失败可重试但不能产生第二只已确认 PA。可以改名字、私聊、投喂/玩耍，缺席不惩罚。风格偏好有来源并支持认可/纠正/忘记。配置模式必须真实模型/生图，缺配置显式失败，不能假候选冒充生成。验收：重复确认被拒绝；账号删除才删除 PA；模型错误不能留下半完成确认。生图应持久异步执行并保存可持续使用的图片，当前同步实现不算完成这一条。

实施方细化（2026-11-10，既定异步要求）：配置模式提交候选返回202与任务ID，轮询本人任务，排队/运行/失败状态明确可见；新申请取代旧申请，旧任务不能覆盖新候选。pgmq只携带用户/任务ID，提示与结果按本人DEK加密。任务租约90秒、最多3次尝试、失败30秒后可重试，失去租约的旧Worker不能提交。账号已删或PA已确认时不再生图；目标仍为图片写私有Storage并由短时URL展示，不把临时供应商URL永久当资产。首个异步实现阶段只接受供应商内联PNG/JPEG/WebP（校验魔数，最大10MB），结果按DEK加密存任务表；不抓取外部URL以避免SSRF。这个分步实现不等于Storage目标完成。demo仍直接返回明确标识的确定性候选，不伪装队列/真实AI。

Storage实施细化（2026-11-10，LA-001/006）：供应商内联图片在Worker校验后按用户DEK加密为私有桶对象，任务结果仅存资产引用；Runtime鉴权后按所有权读取并解密，不签发可绕过账号注销的公网图片URL。展示采用受控API返回内联数据以兼容Web/Android；每次读取均校验本人、有效任务和资产绑定。账号删除先持久冻结账号、清理本人已登记私有资产再删除Auth用户，清理失败明确拒绝完成注销并允许重试。Storage与Auth不是跨服务事务：持久删除栅栏和仅含不透明路径的清理账本在Auth删除后保留，Worker每5分钟重扫已删账号路径，处理在途上传导致的迟到对象，不宣称即时无孤儿或事务性擦除。任务租约失效或完成失败时清理刚上传对象；重试不能覆盖已确认PA资产。保留旧内联结果的兼容读取，不能误称已迁移到Storage。资产内容不写日志，导出可包含本人图片但不得包含Storage服务凭证。实际Storage/RLS仍待真实项目验收。

### LA-002 记忆
本人直接表达→提取候选→先 dont_remember 丢弃→敏感先征求内容绑定同意→三级定级。核心八类及用户明确重要等规则见原始设计。核心冲突先确认，拒绝不替换；核心夜间不降级/覆盖；普通三个不同会话提及升核。普通90/270天、琐碎10/40天淡忘/归档。手账显示理由/来源并可编辑、升降级、删除和纠错反馈。
检索独立加载身份/健康安全/饮食底线/边界规则（20条超出时停止依赖完整约束的建议），另取主题核心与语义+关键词前8条；30天半衰只影响排序，不改变重要性。模糊/淡忘标记不确定。向量同样敏感，嵌入服务失败显式报错，不能无声回退。模型或端点改变不得复用旧向量缓存。
验收：敏感 remember 仍先询问；待同意不检索/普通导出；12个月核心保留；删除无检索/重试复活；嵌入失败不留下半缓存。真实质量另验。

检索与保留实现澄清（2026-11-10，LA-002）：用户明确要求记住、但未归入八类的核心记忆，仍需按相关主题检索，不得从安全/主题/语义三个通道全部漏掉。敏感待确认项过期后清理正文及持久候选，不只是禁止点击；读取工作台与夜间任务均执行清理，不能无限保留过期敏感候选。

确认一致性澄清（2026-11-10，LA-002）：核心冲突卡只能替换它最初指向且仍为当前生效版本的旧记忆；若另一张卡已替换旧版本，过时卡不得历史化新版本或再次覆盖。无效/未来时间戳的待确认项也应拒绝，而不是绕过两分钟有效期。属于既定核心冲突与超时边界的修正。

### LA-003 Agent 与清单
M0 自定义打卡、记录表、计划/清单，专业空间独立。清单含会话/能力/数据/UI/事件五面，未知字段拒绝。更新扩权须明确确认，待确认停止调用；缩权即时应用。拒绝扩权保留旧功能，但已失效授权不能复活。暂停保留数据/授权但不能调用；拆卸删除空间、会话、记录、授权/摘要，保留记忆标记来源删除。验收：专业 A 不能读取 B；PA 记忆不注入专业对话；清单扩权未确认不能记录/聊天/读取；恢复不复活旧版授权。

暂停只读澄清（2026-11-10，LA-003）：暂停停止模型调用、写入及摘要，但本人仍可读取已保留组件记录；待扩权确认仍按既定停止调用策略拒绝读取。不借只读入口恢复会话调用或跨空间权限。

安全实现澄清（2026-11-10，LA-003/004）：PA风格偏好属于PA私有上下文，不能因“用户认可”而默认注入专业Agent；专业会话仅使用该Agent的人设、本人在该会话的历史及显式获准的数据。conversation.enabled=false时禁用该空间会话创建/枚举/读写，不影响仍在清单内的记录组件；记录写入同时满足capabilities与UI组件声明，清单关闭能力不能被旧组件列表绕过。这是原隔离与五面清单约束的修正，不新增专业数据共享范围。

### LA-004 授权
保存敏感记忆、共享字段、读取原文是三个独立同意。默认仅摘要/成绩事件可供 PA，结构字段经网关，专业间禁止直连。授权绑定源、目的、字段、时段、用途、会话（原文）、注册表版本与双方清单版本/策略；变化后重新确认。禁止字段不可覆盖。内部敏感长期仅授权中心主动确认；外部敏感逐次。原文仅 PA、本轮、指定来源/时段/用途，原子消费后不可重放；派生回答只本轮展示，不进历史/记忆/未来上下文。验收：并发只能一次消费；模型失败也不恢复已消费权限；改版、撤销、过期、范围扩张都不复用。

### LA-005 日程与通知
一次性日程保留 UTC 与用户 IANA 时区；到期站内提醒由 PA 展示。仅 PA 发声，专业摘要/成绩汇总进入 PA 待办，早报按本地08:00聚合，紧急用户提醒另行处理。推送隐藏正文，未配置系统推送不能宣称已投递设备。验收：重试不重复提醒，暂停空间不产生摘要，早报时区正确、不泄露专业敏感正文。当前早报/摘要与系统推送未完整实现。

实施方细化（2026-11-10，补齐既定要求而非新增范围）：专业记录仅产生由宿主构造的类型/日期成绩事件，不把自由文本作为默认摘要送 PA；暂停/扩权待确认空间跳过。以用户 IANA 时区的本地日期每日08:00后生成一次站内聚合，不补发历史多天；计数与事件日期可展示，不携带记录内容。用户可修改时区，已生成日期不重复。通知偏好默认 Asia/Shanghai，仅作为可编辑默认值而非推断用户所在地。系统推送继续单独标记未实现。

### LA-006 数据安全与权利
Supabase Auth 验证身份；宿主绑定命名空间，客户端不能自报身份。每用户 DEK 包裹于服务端主密钥，正文/向量加密。数据库独立保护核心、授权一次性消费与追加审计，浏览器不可直接写受控表。账号重新验证后导出/删除，删除密钥及活动派生数据；备份保留遵照实际部署政策。
验收：真实双用户 RLS/所有权/并发/账号级联测试；日志无正文/密钥；无授权行为不能通过通用密文快照绕过核心保护。

重新验证澄清（2026-11-10，LA-006）：账号注销凭据必须属于本人，且认证服务返回有限、非未来、五分钟内的最近登录时间；缺失或无法解析的时间不能因NaN比较结果而通过。沿用既定重新验证要求。

数据库受控角色澄清（2026-11-10，LA-006）：核心编辑/删除由不可登录且不向客户端授予成员资格的专用函数所有者执行；只授予必要表操作与针对该角色的RLS策略，不依赖托管环境未必具备的BYPASSRLS超管权限。触发器先辨认可控函数角色，再对其他删除路径检查账号级联条件，不能为检查Auth存在性而给专用角色增加全局Auth读权。行为脚本验证受控核心删除与普通角色拒绝，未运行仍明确标注。部署权限补充：迁移中的函数所有权转移需显式且仅临时授予部署者专用角色成员资格，完成后撤销；事务RPC所有者需具有私有辅助函数EXECUTE权限，但浏览器与service_role仍无直接辅助函数调用权，不能依赖超管隐式旁路。

LA-006/007 评测工具细化（2026-11-10）：提供离线人工标签与模型预测对照评分入口，不自动产生标签、调用付费模型或把空数据计为通过；报告样本匹配、字段准确率、敏感漏报及缺失预测，人工标签数量不足300明确不达样本要求。报告不包含原始输入或内容；真实模型来源仍需人核验。

LA-003 会话切换隔离澄清（2026-11-10）：切换Agent或会话后，旧列表/历史/发送请求的迟到响应不得覆盖新空间内容；卸载后不再更新UI。采用本地请求序号/作用域及AbortController，不改变服务端授权边界。验收包含延迟响应跨会话切换回归。

### LA-007 配置与验收
显式 demo/configured，不静默降级。演示只回环、不输入私密数据。测试、真实 DB、真实模型、Android、本人体验分别记录。无凭证不是代码功能缺口的替代解释；未运行标记未运行。CI通过不能替代端到端数据安全。

LA-007 供应商传输澄清（2026-11-10）：服务端配置的模型端点不会自动跟随HTTP重定向，避免将私有输入转发到配置之外的新目标；重定向作为供应商错误显式失败。这不等于任意端点SSRF防护，端点配置仍是可信部署权限。

LA-007 Runtime入口防滥用实施细化（2026-11-10）：HTTP入口限制请求正文1MiB、拒绝超限及错误长度声明；模型/生图输入已有字段上限仍保留。进程内限流按已携带凭证的不可逆摘要（未登录统一桶）每分钟60请求，超限429并附重试时间，不把token写日志；它仅为单实例基础防线，不能替代代理层分布式限流、防机器人和真实用户配额。CORS/鉴权仍由业务层验证，限流不能当身份校验。

LA-007 本地数据验收入口细化（2026-11-10）：提供独立Supabase本地项目配置和逐项执行命令，开发者可在具备Docker/CLI时从空库应用迁移并运行SQL及Runtime行为测试；配置不包含真实云项目标识或秘密。没有执行环境时继续标记未执行，不能把提供配置当验收通过。

LA-007 CI验证细化（2026-11-10）：除类型/规则/Web导出外，CI启动独立本地demo Runtime与导出静态服务，执行HTTP三脚本及Chromium浏览器流程，失败上传诊断报告；不借此宣称真实Supabase/供应商/Android已验证。

## 依赖、风险与待确认
- 真实 Supabase 项目/本地 Postgres、模型/生图凭证、Android 设备未具备验收证据。
- 敏感自然语言规则存在漏报风险，不能以词表宣称通用零漏报。
- 逐实体加密与事务投影是研发替代实现，尚未真实 DB 验证，不等于原专用领域表端到端已接通。
- M1 第二阶段须独立比较照片服务；M3 第二官方积木未定，不预设用户已确认。
