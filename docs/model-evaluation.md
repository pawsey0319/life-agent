# 模型质量验收协议

## 不混淆三类证据
1. 领域单测：验证给定分类候选后的确定性定级、授权、夜间时钟等规则。高分不证明模型能正确识别候选。
2. 模拟模型/路由测试：验证离线交互与路由工程，不证明真实对话效果。
3. 配置供应商的真实模型评测：固定模型 ID、日期、温度/提示版本、人工标签和失败样例；只有这类结果才能报告模型质量达标。

## 提取分类（需人工标注 300 条）
每条记录：`id,input,expected:{category,user_signal,is_trait,harm_if_forgotten,emotional_weight,constrains_future,sensitive,event_date?,confidence_band},annotator,reviewer`。
类别包含全部 13 类；覆盖否定/引用/玩笑/第三人称/歧义/中英文/错别字；健康与金融敏感不能只靠含关键词的简单样例。两人分歧先裁决；单人开发至少分两轮盲标并保存修改记录。
逐项 category/各布尔与信号准确率 ≥90%；另外报告敏感召回/漏报、琐碎误存核心率、缺失 JSON/超时率。不能从模型自生成的“标准答案”直接计算人工标注准确率。

## 核心保持
以固定脚本首轮只出现一次核心事实，再插入无关会话。分别拨动3/6/12个月；验证实际送入模型的规则上下文与回答是否正确引用（两层分别计分）。≥98% 是回答保持目标，100% 是安全约束进入规则上下文目标；不能把二者合并。
使用模拟时间，不修改真实账户时钟或生产数据。超过20条安全规则必须可见告警或阻断依赖完整约束的建议，不能一边截断一边计100%。

## 专业调度
初始30条种子在 `tests/fixtures/handoff-cases.json`，覆盖 fitness/nutrition/styling/finance/health，每类6条。人工继续加入隐喻/边界/普通陪伴负例，避免全靠关键词评估。分别检查已安装、未安装、暂停状态；未安装必须提示添加而不是虚构已转交。真实模型不应先给出专业建议再在末尾补一句“建议找专家”。紧急安全情境仍应保留必要的求助提示，不以专业转交阻断紧急求助。

## 敏感与原文
- “记住我的过敏信息”仍必须独立存储确认；否定记忆零正式写入。
- 模型输出 sensitive=false 不可绕开确定性保护；不确定默认先问。
- 工具/模型输出、外部摘要、临时原文及派生回答不得进入提取候选或未来模型上下文。
- 不向真实供应商发送私人数据做初次测试；先用虚构但人工标注样例。

## 离线评分入口

`pnpm evaluate:memory /absolute/labels.json /absolute/predictions.json /absolute/new-report.json` 对照人工标签和已收集模型预测，不调用供应商。labels为数组，每项包含id、annotator、reviewer、expected；预测数组每项为`{id,actual:{...}}`。expected/actual包含category、user_signal、is_trait、harm_if_forgotten、emotional_weight、constrains_future、sensitive。当前运行时类别为八个核心类+general，源方案其他细分类尚未全部展开，不以此工具证明完整13类覆盖。

工具拒绝空标签、重复/未知ID、缺少人工归属及非法标签值；缺失预测按错误计入分母。报告仅含ID、字段指标/失败字段，不复制input或content；ID仍应使用无隐私编号。输出新报告用独占创建，不覆盖已有结果。退出码0仅表示至少300条、完整预测、每字段≥90%、至少含一条敏感正例且无敏感漏报；1表示门槛未满足，2表示输入/文件错误。即使0，也不能证明标签真实人工生成或预测来自真实模型，来源须审查。event_date、confidence_band、核心保持与调度不在该工具评分范围，另验。

## 报告格式
日期、git SHA、供应商/模型 ID（不含秘密）、配置模式、样本数、逐项指标、失败 ID、成本/延迟、未执行项。报告0/300或“待执行”比凭空写100%更准确。只有本地工程测试通过时，交付只能称“工程规则通过，模型待验收”。
