## 必须继续执行的验收

### 1. 真实数据库、队列、Storage（最高优先级）

需要 Docker 或兼容容器运行时、Supabase CLI、psql，以及独立可销毁测试项目；当前主机 PATH 均无相关程序。请按 [部署说明](deployment.md) 启动本地项目、从空库应用迁移，再运行 SQL 行为脚本及 `pnpm test:database`。后者必须显式启用并使用 loopback 测试地址；默认 SKIP 是保护措施，不是成功。

重点核对：迁移角色管理权限、核心更新/删除辅助函数权限、双用户隔离、原子授权消费、CAS 并发、pgmq 租约与重试、图片保密及账号级联清理。任何失败先修复再进入下一层。基线 SQL 曾修订，不可对已经应用旧版本的数据库假定自动生效，应使用空测试库或编写明确升级迁移。

### 2. 配置模式与真实模型

由部署者通过环境变量提供独立测试 Supabase、文本/提取/1024 维嵌入/图像模型配置及主密钥；不要在对话或 Git 中粘贴密钥。按示例配置 Runtime 与 Worker，验证异步生图、模型失败、向量缓存失效和图片清理。配置项存在不代表供应商兼容性已验收。

依 [模型验收协议](model-evaluation.md) 准备至少300条人工标签和实际预测，运行离线评分；标签/真实模型来源须人工审查。另测核心保持、安全约束召回和30题专业调度。不能用生成的合成标签或规则命中率代替真实模型结论。

### 3. Android 与本人体验

JS/Hermes 导出已通过，但尚未执行 Gradle/APK/设备验证。需要 Android SDK/构建环境和设备，检查登录、网络、聊天、确认卡、图片与导出/注销。系统推送目前未实现，仅提供明确标识的站内提醒；不得宣称设备通知已投递。

完成本人连续一周使用后记录可用性问题和隐私预期，不以加速时钟替代体验时间。

## 保留的实现边界

- 活动存储使用逐实体加密投影及受控事务，不是原设计每张专用领域表的逐一接线；必须在真实数据库验证其等价隔离性质。
- 专业问题引导进入对应 Agent，不自动代替用户继续专业会话；默认成绩仅类型/日期，不产生自由文本专业摘要。
- 系统推送、外部适配器、穿搭师、社交及市场不因此完成。M1–M5 保留原路线；M0 验收前不假称整体平台已完成。
- Storage/Auth 无跨服务删除事务；删除栅栏与持久路径账本依靠 Worker 重试收敛，备份另按服务保留政策处理。
