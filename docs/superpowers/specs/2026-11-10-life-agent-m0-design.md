## 3. 技术与运行模式

沿用文档：Expo + React Native + TypeScript + Expo Router（Web/Android）；Supabase Auth/Postgres/Storage/Realtime；Node.js TypeScript 常驻 Runtime；pgvector；pgmq Worker；用途分离的 OpenAI 兼容模型适配器。

研发方案允许 Hono/Fastify 二选一；建议 Hono（实施方选择，不视为用户已确认）。客户端、Runtime 和共享合同分包，数据库迁移独立管理。

两种运行方式：
- 显式本地演示模式：无需云账号和模型密钥，用可预测的模拟模型验证交互；页面明确显示“演示模式”，不宣称真实 AI 或生产安全。不得连接真实外部服务。
- 配置模式：Supabase 登录、持久化、Runtime 鉴权、Worker 和真实模型。缺少必要配置必须明确报错，不静默退回演示。密钥只在服务端。

云资源创建、上线、付费生图、Android 签名发布不属于默认动作；提供配置与部署说明。只有实际执行并通过才标记为已验证。

## 4. 用户可见流程

### 4.1 PA

首次进入填写名字、外观期待、性格、相处方式与排除特征；候选生成失败可重试，确认后初始形象锁定。一个账号只能有一个 PA，改名不等于重新孵化。

首页为 PA 入口，能聊天、进入记忆手账、日程和授权中心。专业问题转交已安装的对应 Agent，未安装则提示添加，不编造专业答案。孵化、图像候选和确认必须分别表示处理中、失败、已确认状态。

M0 保留基础陪伴互动及风格纠正入口；真实经历进化的复杂管线按路线后续完善，不用点击按钮伪造自动进化。

### 4.2 团队与自定义 Agent

初始只有 PA。用户创建一个 platform 模式 Agent，填写名称、领域和人设，选择通用组件。建议 M0 提供打卡、记录表、计划/清单基本可写组件；图表和图集若未实装不得标记已支持。

每个 Agent 有聊天与专属组件页。添加、暂停、恢复、更新、拆卸均有实际状态；暂停停止调用和摘要。拆卸前提示导出，拆卸清除该积木数据、授权、会话、队列及摘要，保留记忆引用需标记“来源已删除”。

## 5. 记忆合同

重要性与活跃度分离，等级为 core/normal/trivial；来源与理由必须可展示。类别清单驱动核心判定，模型只分类，不直接决定权限或遗忘。

判定次序对研发伪代码作安全澄清：
1. 用户说不用记：DROP。
2. 敏感候选且没有绑定该候选的明确同意：ASK_FIRST，不能因为 remember/important 跳过。候选临时保存与长期记忆分开，待同意内容不参与检索和普通导出。
3. 用户明确记住：core/user。
4. 命中核心类别：core/rule；遗忘伤害或高情感分量：core/model；低置信度：core/uncertain；其余按长期特质、约束和状态分 normal/trivial。

核心冲突：先确认再替换，旧值为 historical；拒绝则丢弃候选。普通/琐碎确定冲突可直接替换，不确定则确认。候选、确认及替换操作要求本人且幂等。

检索：健康安全、饮食底线、个人禁忌、身份事实走规则读取通道（上限 20 条、截断告警）；其他核心按领域读取；其他 active/faded 记忆走语义+关键词混合检索，最多 8 条，淡化附不确定标记。历史、待确认和归档不默认参与回答。正文应用层加密与普通 Postgres FTS 不兼容；M0 建议对本人权限过滤后的有限候选在 Runtime 解密后做关键词排序，不另存明文 FTS。安全关键约束超过规则通道预算时显式报告溢出并暂停依赖完整约束的建议，不能静默截断后宣称 100% 召回。

夜间整理：normal 90 天淡化、总计约 270 天未用归档；trivial 10 天淡化、总计约 40 天未用归档；同 subject 在至少三个不同会话重复的 normal 升 core。core 不淡化、不归档、不自动合并/替换；触发器和受控写入接口双重保护，避免普通客户端直接绕过。

手账：来源、等级、理由、最近记住、拿不准栏目；编辑、升降级、钉住、删除、恢复归档；纠错写 feedback。删除物理清理正文、索引与派生检索数据，审计仅存标识和时间、不存内容。被删除记忆不得被遗留队列重新写回。

## 6. 授权与积木合同

五接口面 manifest：conversation、capabilities、data、ui、events。使用版本化验证，未知字段、未开放工具与 bridge 方法拒绝；新增申请范围必须重新确认。M0 不启用外部适配器，但合同和测试保留外部敏感逐次确认规则。

身份由已鉴权会话在服务端注入，客户端/模型提供的 user_id、block_id 不能成为可信宿主身份。读取自己的数据走 namespace API，跨空间只有 gateway 受控路径。

授权决定使用服务端字段词表、积木身份与状态，不相信调用方传入的 external/sensitivity/purpose 标志。用途来自清单，时间范围明确。

普通字段可本次或长期；内部敏感长期授权只能在授权中心主动设置。外部敏感字段每次确认，不能复用长期授权。

原文是专门例外：仅 PA 可向用户申请指定 Agent、指定时段和本轮回答的单次读取；专业 Agent 永远不可读其他 Agent 原文。不得将此例外误写成“所有 forbidden 都可授权”。原文授权绑定会话/请求、有效期与用途，原子消费，重复和并发读取不得复用；原文、引用及派生回答不得自动进入记忆提取队列，若另存记忆要独立询问。原文与其派生回答不进入后续模型上下文；只读原文和临时模型上下文本轮结束清除。对已展示派生回答的历史保留策略需在实施前明确；默认建议仅本轮展示并标注临时内容。拒绝记忆不等于删除用户源聊天消息，聊天记录仍按加密历史策略保留，但不得因此形成长期记忆。自动提取只处理用户本人直接发送且非外部/原文派生的消息，不从模型回复和工具输出重新提取。

卡片两分钟超时拒绝；审计记录每次决定、读取和撤销，不记录字段值。撤销不会“撤回已读信息”，界面要区分日志与可撤销的有效授权。

## 7. 存储和执行边界

基于研发方案核心表：users、pa、blocks、sessions/messages、block_records、field_registry、grants、grant_requests、audit_log、pa_inbox、memories、memory_tier_feedback、core_categories。关系外键必须阻止跨用户关联；不是只有各表 user_id 的 RLS 就够。

客户端不能直接修改授权、审计、核心记忆状态或受控隔离表；通过鉴权 Runtime/RPC 操作。审计只追加，用户可读不能改；Runtime 不向积木暴露服务角色或 SQL。

消息与记忆正文按每用户数据密钥加密，主密钥包裹；密钥不入库明文、不写仓库。日志和错误避免正文、token 和秘密。向量可能包含敏感信息，不能把向量“不可逆”当绝对安全保证。

异步队列包含重试、幂等键和状态，删除、拆卸、撤销后重试必须重新检查，不能复活数据。日程仅平台内部，提醒进入 PA 发声队列；专业积木不直接推送。真实设备推送依赖 Expo 配置，未配置时明确显示未启用。

## 9. 审查后的实施方默认选择

以下是实施建议，不表示用户已逐项确认：
- 自定义 Agent 首期实装打卡、记录表、计划/清单；字段词表先覆盖平台日程、习惯完成、普通记录及敏感健康样例，用于实际授权与测试。其余组件后续扩展。
- 配置模式包含文本与首图 OpenAI 兼容适配、异步候选生成与确认锁；必须配置图像供应商才能真实生成，缺配置明确报错，不把内置占位当生成。实际供应商兼容性列为独立验收，不因适配器单测通过宣称已验证。
- 基础陪伴包含投喂/玩耍的正向事件记录，不惩罚缺席；风格条目绑定来源，支持认可、纠正、忘记。复杂进化不在 M0 完成声明中。
- 敏感范围按产品列举健康状况、伤病、身高/体重/体脂、经期、消费金额、身体照片、他人隐私覆盖；模型分类之外加确定性保护，模糊候选默认先问。仍须真实标注评测，不能宣称规则可保证所有自然语言识别零漏报。
- 日程首期一次性事件/提醒，保存 UTC 时间和用户 IANA 时区，不支持重复规则。无 Expo Push 配置时通过站内通知与 PA 待办展示提醒，明确不保证系统推送。
- M0 包含本人 JSON 数据导出及重新验证身份后的账号删除，级联清除线上活动数据与密钥。备份按实际部署服务保留策略另列，不宣称能够即时擦除已生成的外部备份。
- 对原文读取产生的派生内容默认只在本轮展示、不进入后续模型上下文；拒绝记忆不会删除源聊天记录，删除聊天与删除记忆为独立操作。
- 保留主文档规定的夜间淡忘与跨三个不同会话自动升核，不采纳审查中改变既定产品行为的缩围建议；安全修正不改变产品里程碑。
