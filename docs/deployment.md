# 配置部署与运维检查表

> 本文是操作说明，不代表已创建云资源或已通过生产验收。首次仅本人自用；不要把 demo Runtime 暴露到公网。

## 两种模式
- **demo**：仅本地回环监听、模拟模型、独立可重置状态；不输入真实健康/金融等私人数据。客户端常驻演示标识。
- **configured**：缺 Supabase、主密钥或所需模型配置即报错；不能悄悄退回 demo。鉴权必须验证 Supabase 用户，不能仅解析未验签 JWT。

具体环境变量及启动命令见[README](../README.md)、[服务端环境示例](../packages/runtime/.env.example)和[客户端环境示例](../apps/mobile/.env.example)。主密钥必须是32字节随机值的 base64 编码，例如在可信终端用 `openssl rand -base64 32` 生成，勿复制演示常量。示例文件不自动加载，显式导出环境变量。

## Supabase
1. 新建独立项目；不要导入原型用户或复用其他项目密钥。
2. 应用 `supabase/migrations`，确认 pgvector/pgmq 扩展在目标托管版本可用。数据库管理员执行迁移，客户端永远不拿服务角色。
3. 对允许直读的本人业务表启用 RLS；敏感受控表默认不开放写入。逐表验证 anon/本人/其他用户/Runtime 角色。
4. 以两个真实用户、两个不同命名空间测试跨用户外键、直接表访问、核心夜间修改、审计删除与单次授权并发。
5. 活动权威为 `runtime_entities` 逐实体密文，事务 RPC `save_runtime_projection` 同时执行关系/核心保护、审计追加、CAS；`runtime_projection_state` 只保存修订与包裹密钥。原版 `runtime_state` 遗留数据会触发 `MIGRATION_REQUIRED`，没有隐式升级。新项目必须应用全部迁移（领域、投影、队列与资产）；旧内测项目在离线受控迁移前不要用新代码覆盖数据。原始专用领域表尚未作为 Runtime 活动数据源，不把两套表“双写”混称集成。迁移未经真实 Postgres 执行，不宣称数据层隔离通过。

## Runtime
- 使用 Node 22+ 的常驻进程或容器，TLS 由反向代理终止。只暴露 API；管理/worker 端点不得公开。
- 配置明确的浏览器 Origin 白名单；不得 credentials + 任意 Origin。Runtime入口已限制正文1MiB并验证长度声明；配置模式按凭证摘要/匿名桶每分钟60请求（demo本机600），超限429；最多10000个活动桶，不能用未验证凭证的限流代替鉴权。它仅为单实例防线，代理层仍须限制连接/读取超时、分布式速率和真实用户模型配额，避免慢速请求或随机token绕过业务费用控制。
- 每用户数据密钥用高熵主密钥包裹；主密钥放 KMS/部署秘密管理器，不在客户端、日志或 git。密钥丢失导致历史不可解密；轮换前先测试重新包裹与恢复。
- 模型按用途分离配置（对话、提取、嵌入、生图），供应商是用户数据处理方；隐私政策须说明发出的字段与保留策略。
- 外部模型生成的 JSON 先 schema 验证；文本不能变成数据库权限、任意工具或 SQL。模型请求以redirect:error拒绝任何HTTP重定向（不只私网目标），不将私有输入转发到配置外的新地址；配置端点本身仍由可信部署者审查，这不是任意端点的SSRF隔离。
- 数据库服务角色仅 Runtime 使用；不得透传给积木、客户端或导出。
- 多实例必须使用数据库事务/锁或 CAS，不能依赖单进程 Map 保证一次性授权；未验证并发时只运行单实例，且明确不构成完整生产隔离保证。

## 当前内测 Worker 启动

服务端环境配置完成后运行 `RUNTIME_MODE=configured pnpm --filter @life-agent/runtime worker`。`WORKER_INTERVAL_MS` 默认60000，`WORKER_ONCE=true` 可单次执行后退出。它轮询加密状态、执行夜间整理/站内到期提醒与本地08:00成绩早报，并通过CAS提交；冲突下一轮重新读取。每轮另消费一个pgmq生图任务，90秒租约、最多3次领取、固定30秒延迟重试，状态保存在runtime_jobs；完整失败管理台仍未实现。模型单次请求60秒超时，不等于整个任务严格小于90秒，慢数据库或进程暂停仍可能导致租约过期与重复供应商费用。

先应用全部迁移，包括异步队列迁移。配置模式 `POST /api/pa/candidates` 返回202与任务ID；客户端轮询 `GET /api/pa/candidate-jobs/:id`，仅当前最新任务可采用，PA确认/账号删除后不得采用迟到结果。没有Worker时任务会保持排队，不自动同步调用或切回演示。

输入和结果均按本人DEK加密，pgmq仅含任务与账号标识。当前只接受供应商返回的base64 PNG/JPEG/WebP（签名校验、最大10MB），不下载供应商URL，避免隐式SSRF。新图像按本人DEK加密上传私有`life-agent-assets`桶，任务/候选只存引用。Runtime逐次验证资产owner/id/path/job及ready状态后解密为内联数据展示，不签发公共/短时直达Storage链接；旧内联结果兼容读取但不自动迁移。10MB原图因dataURL及密文编码约放大1.78倍，传输/缩略图优化未实现。任务入队与pgmq发送是一个数据库事务，但入队与候选状态CAS分属不同事务：失败可产生无主最新任务，必须重试生成，不自动采用；外部生成费用无法保证exactly-once。

## 私有图片与注销清理

应用`20261110030000_assets.sql`创建私有桶、资产预约、持久删除栅栏和清理账本。浏览器没有直接Storage读写策略；Runtime/Worker服务角色上传的必须是密文，不能把桶切公开。先登记预约再上传、验证租约和删除栅栏后标记ready；明确租约失败尽力移除新对象；若完成RPC网络响应丢失，可能已提交成功，不盲删资产，保留账本待状态核对，避免破坏成功候选。未引用但无法判断的资产可保留到注销清理。Worker每轮先执行资产清理，失败不会记录成功，后续重试。

账号注销在重新验证后先冻结账号，移除已登记对象，再删除Auth与活动密文/DEK；清理失败账号保持冻结，仅允许重试注销。Storage与Auth/Postgres不支持跨服务原子删除：在途上传可能迟到，`runtime_account_fences`与不透明路径清理账本故意不随Auth级联，Worker每5分钟重复清理以收敛迟到对象。账本不含图片正文/DEK但含用户UUID及不透明路径，属于保留的最小删除运维元数据；不能宣称账号删除后数据库所有字节或外部备份都已即时消失。暂停Worker会暂停后续收敛，部署监控必须包含清理失败计数。待真实云项目验证权限和并发竞态。

## Worker 和通知（目标检查表）
- Worker 每次执行重查账户、源消息、积木状态、授权有效期；幂等键+重试上限+失败可见。删除/拆卸时取消待办。
- 日程保存 UTC 与 IANA 时区；一次性提醒到期后只发一次。专业 Agent 只进 PA 收件箱，不直接推送。
- 默认早报按用户时区 08:00，用户紧急提醒独立；系统推送不展示敏感正文。
- 没有 Expo Push 凭据/设备 token 时只用站内收件箱，不能宣称 App 关闭时可收到系统通知。

## 删除与备份
- 导出只包含已同意的本人数据，不含密钥、待确认候选与临时原文派生回复。
- 删除记忆包含行、向量、词法派生物/缓存及队列源阻断；不保留内容到 audit。
- 拆卸包含命名空间记录/会话/授权/队列/摘要，保留的 PA 记忆仅标注来源已删。
- 账号注销重新验证身份，删除在线活动数据与 DEK，再删除 Auth 账户；失败必须可见且能安全重试。
- 外部导出文件、供应商日志、托管备份不可能凭线上 DELETE 即刻抹除。部署者必须登记备份周期/最长保留/恢复时应用删除清单策略。

## 本地数据库测试入口

仓库提供独立本地配置 `supabase/config.toml`（固定回环端口、不含云项目引用；Storage上限25MiB用于加密编码放大）。具备Docker和Supabase CLI后，在仓库根执行 `supabase start`，然后 `supabase db reset` 从空库应用全部迁移；这是破坏性的本地测试重置，不要链接生产项目执行。配置目前仅通过TOML语法检查，CLI版本/扩展镜像兼容性尚未运行验证。

使用本地数据库地址分别执行 `psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f supabase/scripts/verify_projection.sql`、`verify_jobs.sql`、`verify_assets.sql`（后两者同目录）。`verify_m0.sql` 依赖pgTAP，应通过支持pgTAP的测试入口执行并检查断言结果，不能仅看psql退出状态。各行为脚本回滚夹具。执行前确认DATABASE_URL明确指向独立本地54322端口。

应用迁移后，使用独立本地 Supabase 的环境变量运行：

```bash
RUN_LOCAL_DATABASE_TESTS=1 SUPABASE_URL=http://127.0.0.1:54321 \
  SUPABASE_SERVICE_ROLE_KEY=... SUPABASE_ANON_KEY=... pnpm test:database
```

此测试创建随机测试账号，验证加密持久化、CAS 双写、浏览器写入/RPC拒绝与账号清理，最后删除测试账号。它拒绝非 loopback URL；未显式开启时报告 SKIP（不是通过数据库验收）。`supabase/scripts/verify_m0.sql` 是额外 schema/权限断言，不替代行为测试。不要把部署密钥写入命令历史或仓库，实际执行推荐从临时安全环境注入。

## 上线前必验
- 真 Supabase RLS/RPC/触发器/并发一次性凭证与跨用户用例。
- 真模型提取：300 条人工标注，每个字段 ≥90%；不把生成的测试样例等同人工标注。
- 真模型核心保持 ≥98%，安全规则上下文召回100%，敏感未同意正式写入0；失败样例进入回归。
- 真实生图候选确认/失败重试、真实 Web 与 Android 开发构建、系统推送和连续一周本人体验。
- M1–M5 未完成项保持明确，不以 UI 占位宣称支持外部服务/社交/市场。
